# ⟦AI⟧ SABES 디자인 피드백 · 2026-11-06

직접 사용자 요청: 디자인 스킬을 활용한 주요 문제점·개선안 제안. 본격적인 코딩 없이 검토.
이하 내용은 AI의 미채택 개선 제안. 제품 코드·기존 디자인 규약 변경 없음.

## 검토 방식과 전체 인상

Operate 모드. 디자인 판단과 기계적·브라우저 근거를 두 독립 검토로 분리하고, 디자인 검토 완료 후 검출 결과를 종합했다. 대상은 sabes_page.py와 광학 테이블 frontend, 데스크톱1440×900·모바일390×844, Part1/2·편집기·계측·Detection·Power budget.

광학 토폴로지·실험 소자 용어·광선 색·가상 계측기가 SABES 고유의 성격을 만든다. 가장 큰 개선 기회는 테이블에서 조절하고 같은 화면에서 판독하는 작업공간이다.

## 유지할 강점

- 기존 console/Plex 글꼴·절제된 바탕·일관된 광학 기호.
- 상단 세 관측값, 작은 모델 상태 배지, 별표의 기존 뜻.
- 장치 정보·출처·실측 기준의 풍부함. 정상 작동한 Fit/100%/pan, 소자 키보드 선택·포커스·Enter/Escape.

## 주요 문제와 개선안

1. **P1 — 테이블과 측정 피드백의 공간적 분리.** 1440×900에서 테이블이 y≈696px부터 시작하며, 계측 선택·측정 결과는 약630px 캔버스 아래에 있다. 광로 선택 뒤 결과를 읽으려면 시선을 옮기는 수준을 넘어 페이지를 왕복한다. 소개·기준 설명은 상세로 옮기고 경고는 짧고 눈에 띄는 상태행과 전체 설명 접근으로 정리한다. 기존 사이드바를 선택 소자/계측용 문맥 패널로 재활용하거나 테이블 안에 접을 수 있는 판독 선반을 둔다. 새 패널을 추가해 도식 폭을 더 좁히는 방식은 피하고, 상세 trace는 확장한다. 제안 도구: impeccable layout / distill.

2. **P1 — EOM 전송표의 실제 표시 깨짐.** Power budget의 EOM mode → etalon transfer는 열이 있는 표가 아니라 파이프와 수치가 이어진 문단으로 보인다. 헤더의 |Eout/Ein|가 Markdown 구분자와 충돌하고 공용 생성기가 escape하지 않는다(sabes_page.py:865–869,893). 정렬된 구조적 표로 복원하고 원하는 sideband 행을 강조한다. 열10개의 전체 값은 가로 스크롤로 보존한다. 값·수식 변경 제안 아님. 제안 도구: impeccable harden / layout.

3. **P1 — 광로 측정의 키보드 대안과 작은 터치 대상.** 소자 키보드 선택은 정상이나 측정점 배치는 좌표 클릭에 의존한다. 광로 구간 검색/선택과 다음·이전 측정점 조작을 제공해 같은 probe 상태를 사용하게 한다. 모바일 Fit30%에서 라벨의 유효 크기는 약3.54px, 작은 소자 hit 영역은 약8.3px이며 100%에서는 라벨12px·작은 소자28px이다. 확대·pan·하드웨어 선택 대안은 이미 있으므로 Fit을 조망용으로 명확히 하고 100% 읽기/편집 진입을 쉽게 만든다. 29×34px의 확대 버튼과 정밀 소자 선택은 더 편한 터치 영역을 갖게 한다. 제안 도구: impeccable adapt / harden.

4. **P2 — 편집창에서 출처가 입력보다 먼저 보임.** EOM의 여러 근거 문단 뒤에 조절값이 나오고, 모바일 Rb cell은 장치·보드·센서 기록을 읽은 뒤 Temperature에 도달한다. 조절값을 먼저 두고 하드웨어·출처는 접힌 상세로 둔다. 선택 소자의 정보는 한 곳에서 읽고, 반복 조절에는 안정적인 문맥 패널/시트를 사용한다. 즉시 반영 여부와 소자별 되돌림도 설계한다. 상세 근거를 삭제하자는 제안 아님. 제안 도구: impeccable distill / clarify.

5. **P2 — 상세 데이터가 판단 단위로 묶이지 않음.** Detection의29행은 모델 해석·기하·RIN·전자잡음·양팔 데이터를 동등하게 나열한다. Power budget의28단계도 경로명이 반복되고 셀 입력 요약은 아래쪽에 있다. 검출·기하·잡음으로 묶고 probe/conjugate를 나란히 비교한다. 파워는 중요한 입출력·손실 요약을 먼저, 단계별 원장은 뒤에 둔다. 상단 카드에서 관련 상세 구역으로 이동할 수 있으면 값의 근거를 찾기 쉽다. 계산 해석과 범위는 해당 진단값 옆에 유지한다. 제안 도구: impeccable layout / clarify.

## 작은 마감

- 선택된 Fit/100% 글자 대비는 검출기 기준3.6:1. 배경을 유지하면서 글자색을 짙게 하는 방향.
- h1→h6 제목 단계 건너뜀은 의미 구조 개선 대상.
- Gain 한 카드 안에서 G_s와 G_c를 각 수치에 직접 붙이면 순서 해석 부담 감소.
- Solve knobs는 목표출력에 맞춘다는 결과를 드러내는 명칭이 적합.
- 7개 탭의 중요도를 나눠 Optical table/Spectrum/Detection/Power budget을 작업 탭으로, 장치·보정·유도값을 참조 접근으로 구분하는 안.

## 인지 부담과 사용자 관점

물리 문제의 고유 복잡도에 불필요한 화면 이동·기억 부담이 더해진다. 반복 튜닝 사용자는 모달과 판독 위치를 왕복한다. 키보드 사용자는 소자를 선택할 수 있지만 광로 측정 대안이 부족하다. 모바일 사용자는 첫844px 안에 작업 탭에도 도달하지 못한다(탭 시작 y≈851.8px).

## 기계적 근거와 한계

CLI detector는 frontend markup에1회 실행, 경고1건(low-contrast). 브라우저 초기 상태에서 desktop/mobile 각각4건이지만 중복 상태를 합산한 고유8문제가 아니다. 작은 글자11.2px·외톨이 줄바꿈·제목 단계·선택 버튼 대비가 주된 advisory다. detector overlay 자체를 다시 검사해 생긴 text-occlusion2건은 앱의 잘림으로 계산하지 않았다.

소자 키보드 포커스와 Enter/Escape는 실제 확인. 100% 확대·pan과 Inspect hardware 대안이 있으며 전체 페이지 가로 overflow는 확인되지 않았다. 물리 터치 기기·스크린리더·브라우저200% 전수 검사는 하지 않았다.
